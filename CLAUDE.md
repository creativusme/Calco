# Calco

Open-source 3D scanning system: iPhone capture app (LiDAR + ARKit poses + photos) and a Windows desktop app that does the heavy reconstruction locally. No cloud, no subscription. Owner talks Italian in chat; **all code, UI text and docs are in English** (exception: `docs/collaudo.md`, the owner's field test sheet, is Italian).

## Layout

| Path | What | Stack |
|---|---|---|
| `engine/` | Reconstruction engine, CLI, local HTTP server | Python 3.12, pycolmap, Open3D, OpenCV, trimesh, FastAPI |
| `desktop/` | Desktop UI (library, viewer, queue, export) | React + TypeScript + Vite + three.js, wrapped by Tauri (Rust) |
| `ios/` | Capture app | Swift, SwiftUI, ARKit, SceneKit. Project generated by XcodeGen |
| `docs/` | Capture format spec, field test checklist, roadmap | Markdown |

The phone never talks to the UI. Two transfer paths, both into the engine's library:
- **Pairing** (`engine/calco/pairing.py`, `ios/Calco/Pairing.swift`): no discovery. The computer shows a network code (its IPv4 in Crockford base 32, `XXXX-XXX`) and a 6-digit password; every non-local request needs `X-Calco-Pin`, and the phone checks the same password before serving the cable link.
- **Wi-Fi push**: the phone uploads to the **engine server** (`calco serve`, port 7878) and pings `/api/hello` every 3 s with `X-Calco-Device` and `X-Calco-Pin`.
- **Cable pull**: the phone serves its captures on port 7879 (`ios/Calco/PhoneServer.swift`); the engine reaches it through Apple's usbmuxd on 127.0.0.1:27015 (`engine/calco/usb.py`). Needs Apple Devices/iTunes on Windows, no firewall rule. Captures marked `sent` on the phone are never pulled again.

The desktop UI is a client of the same HTTP API, so it also runs in a plain browser (`npm run dev`).

## Decisions already made (do not re-litigate)

- Name **Calco**. License **AGPL-3.0** + CLA for future dual licensing. Dependencies may be GPL/AGPL (OpenMVS).
- The **capture bundle** (`docs/capture-format.md`) is the contract between phone and engine. Change the spec first, bump `version`, keep the engine reading old versions.
- Cameras come from the ARKit poses: triangulate with them, then bundle-adjust (`_known_pose_model` in `sfm.py`). Incremental mapping is only the fallback (no poses, or it fails) because it builds wrong forks on repetitive textures (seen on a real capture: 16 photos 30 cm off). Photos without a pose (macro details) are registered afterwards against the fixed model. LiDAR alone is only ±1 cm.
- Precision matters (3D-printed parts must fit): scale comes from the **scan mat** (AprilTag 36h11) or a manual caliper measurement, and every result carries an accuracy report.
- "Automatic first": the engine picks the pipeline from the bundle (`plan()` in `engine/calco/pipeline.py`); every choice stays overridable.
- No Mac: iOS builds run in GitHub Actions (`.github/workflows/ios.yml`) and produce an **unsigned IPA** the owner signs with Sideloadly. Swift code cannot be compiled locally, so keep it simple and check CI.
- External tools are downloaded into `%LOCALAPPDATA%/Calco/tools`, never committed: OpenMVS (`calco tools install`) and the COLMAP CUDA build (`calco tools install-gpu`). The COLMAP binary and `pycolmap` must be the same version: they share the database. The Gaussian splat engine (PyTorch + gsplat) lives in its own Python 3.10 there (`tools/splat`, made with `uv`; gsplat has Windows wheels only for 3.10); `calco/splat_train.py` runs inside it with `python -I` and must not import the `calco` package. `calco tools install` sets up everything that is missing.
- The app must never call a cloud or AI service. Anything learned-model based (masks, features) has to run locally.
- UI identity: instrument look (ink surfaces, hairlines, 3 px corners, one lime signal colour, numbers in mono). Fonts Switzer / Cabinet Grotesk / JetBrains Mono from Fontshare, fetched by `desktop/scripts/fonts.mjs`, not committed.

Read `docs/roadmap.md` first: it says what is verified and what has never been compiled or run.

## Commands

```bash
# engine (from engine/)
.venv/Scripts/python -m pytest -q                 # tests (synthetic capture, no phone needed)
.venv/Scripts/python -m calco serve               # API on http://localhost:7878
.venv/Scripts/python -m calco process <bundle> --preset medium
.venv/Scripts/python -m calco synth out.calco     # make a synthetic capture bundle

# desktop (from desktop/)
npm run dev          # UI in the browser against a running engine
npm run tauri dev    # native window (needs Rust toolchain)
```

## Conventions

- Engine world frame = ARKit world: metres, +Y up, right-handed. Camera-to-world poses, camera looks down −Z (OpenGL style). Convert to COLMAP/OpenCV (+Z forward, +Y down) only inside `sfm.py`.
- Pipeline stages are pure functions `stage(ctx) -> None` that read/write files in the job work dir, so any stage can be re-run alone.
- Keep it lean: no speculative abstractions, no features for a public release until the owner asks.
